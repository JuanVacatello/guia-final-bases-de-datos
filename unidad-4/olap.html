OLTP, OLAP y Data Warehouse

El tema de teoría más tomado desde 2023. Casi siempre es «compare OLTP y OLAP»; si no, ETL y modelo estrella. Con una tabla y dos dibujos se escribe la respuesta completa.

🟦 En 30 segundos Diagramas Tablas 🟥 Trampas 🟪 Respuestas modelo 🟩 Ejercitá

🟦 En 30 segundos

  • OLTP = el sistema del día a día: muchas transacciones cortas (vender, cobrar), datos actuales, modelo normalizado, prioridad en ACID y concurrencia.
  • OLAP = el análisis para decidir: pocas consultas enormes sobre datos históricos, modelo desnormalizado (estrella), solo lectura, se mira en cubos (por producto, por mes, por sucursal).
  • El Data Warehouse junta datos de muchas fuentes (incluso heterogéneas) con un proceso ETL: extraer, transformar (limpiar, unificar) en una staging area y cargar. Es integrado, orientado a temas, histórico y no volátil. Un Data Mart es un DW de un área.
  • Modelo estrella: una tabla de hechos con las medidas (importe, cantidad) y FK a las dimensiones (tiempo, producto, cliente). Normalizar las dimensiones da el copo de nieve.

    Compare OLTP y OLAP en cuanto a su utilización y diseño de base de datos 5 veces

    OLTP (On-Line Transaction Processing) son los sistemas que operan el negocio: registrar ventas, cobros, reservas. Tienen muchos usuarios concurrentes que ejecutan transacciones cortas que leen y modifican pocas filas, sobre datos actuales. Por eso priorizan las propiedades ACID, la concurrencia y el tiempo de respuesta, y usan un modelo normalizado (3FN) que evita redundancia y anomalías al modificar, con pocos índices. Ejemplo: el sistema de cajas de un supermercado.

    OLAP (On-Line Analytical Processing) son los sistemas de soporte a decisiones: pocos usuarios (gerentes, analistas) hacen consultas complejas que leen y agregan millones de filas de datos históricos. Los datos se cargan periódicamente desde los OLTP mediante ETL a un Data Warehouse y no se modifican. Se usa un modelo desnormalizado, en estrella (tabla de hechos con medidas y dimensiones alrededor), con muchos índices y resúmenes precalculados, y se analiza en cubos (drill-down, roll-up, slice). Ejemplo: ventas por sucursal y trimestre de los últimos cinco años.

    En síntesis: OLTP está optimizado para escribir rápido y consistente; OLAP, para leer y resumir mucho.

    Funcionalidad de una ETL y concepto de staging area 2 veces

    El proceso ETL (Extract, Transform, Load) es el que alimenta un Data Warehouse. Extrae los datos de las fuentes, que pueden ser heterogéneas (bases de distintos motores, planillas, archivos); los transforma: limpia errores, completa faltantes, unifica códigos y formatos (fechas, monedas, «M»/«Masculino»), elimina duplicados, integra los datos de distintas fuentes y calcula valores derivados; y los carga en el DW, primero las dimensiones y después los hechos. Corre de forma periódica, normalmente fuera del horario de operación.

    La staging area es un área de almacenamiento intermedia entre las fuentes y el DW donde se dejan los datos extraídos para transformarlos. Así la extracción es rápida y no frena a los sistemas OLTP, las transformaciones no ensucian el DW si fallan a mitad de camino, y se puede reprocesar o auditar lo extraído.

    Salió el 07/03/2023 (con modelo estrella) y el 27/09/2023.

    Explique el modelo estrella para un Data Warehouse 3 veces

    El modelo estrella es el diseño típico de un Data Warehouse o Data Mart. En el centro hay una tabla de hechos, que registra los eventos del negocio a analizar (por ejemplo, cada venta) con sus medidas numéricas (cantidad, importe) y una clave foránea a cada dimensión. Alrededor están las tablas de dimensiones, que describen el contexto del hecho: tiempo (día, mes, trimestre, año), producto (nombre, rubro, marca), cliente, sucursal.

    Las dimensiones están desnormalizadas: toda la jerarquía en una sola tabla, para que cualquier consulta sea un join de los hechos con cada dimensión que necesite y un GROUP BY. Eso hace las consultas simples y rápidas, a costa de redundancia, que no importa porque los datos no se modifican. Cada dimensión equivale a un eje del cubo.

    Si se normalizan las dimensiones, el resultado es el modelo copo de nieve. Para cargarlo, primero las dimensiones y después los hechos.

    Salió el 07/03/2023, el 23/05/2023 (Data Mart) y el 18/10/2024.
