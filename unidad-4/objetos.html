Unidad 4: Bases de datos

Constraints, triggers, vistas y SP

Los objetos de base de datos y para qué sirve cada uno. Es la fuente de V/F más grande de la unidad 4 y la base de los prácticos de implementar reglas (tipo C), que casi siempre se resuelven con un trigger.

🟦 En 30 segundos Diagramas Tablas Plantillas 🟥 Trampas 🟪 Respuestas modelo 🟩 Ejercitá

🟦 En 30 segundos

  • Constraints (PK, FK, UNIQUE, CHECK, DEFAULT, NOT NULL): reglas declarativas que el motor verifica solo. Primera opción para la integridad. UNIQUE admite un NULL en SQL Server; CHECK mira solo la fila.
  • Trigger: código que se dispara con INSERT, UPDATE o DELETE, en la misma transacción. AFTER (valida y hace ROLLBACK; puede haber varios por evento) o INSTEAD OF (reemplaza la operación; uno solo por evento). Usa las tablas inserted y deleted y se dispara una vez por sentencia, no por fila.
  • Vista: una consulta guardada con nombre. Sirve para seguridad y para simplificar; no guarda datos. Se puede insertar por ella si es simple o con un INSTEAD OF. Snapshot: copia guardada de los datos en un momento.
  • Stored procedure: puede modificar datos y manejar transacciones; se ejecuta con EXEC. Función: devuelve un valor o una tabla, se usa dentro de un SELECT y no puede modificar tablas.

Trigger AFTER que valida una regla (multifila)

Final 22/12/2022: campeón ≠ subcampeón y al menos 4 años entre mundiales.

-- Motor: SQL Server (T-SQL)
CREATE TRIGGER tr_mundial_reglas ON MundialFutbol
AFTER INSERT, UPDATE
AS
BEGIN
  SET NOCOUNT ON;

  -- regla 1: mira solo la fila (también se puede con CHECK)
  IF EXISTS (SELECT 1 FROM inserted WHERE PaisCampeon = PaisSubCampeon)
  BEGIN
    ROLLBACK TRANSACTION;
    THROW 50001, 'El campeón y el subcampeón no pueden ser el mismo país.', 1;
  END

  -- regla 2: mira otras filas de la tabla
  IF EXISTS (SELECT 1
               FROM inserted i
               JOIN MundialFutbol m
                 ON m.IdMundial <> i.IdMundial
                AND ABS(m.Anio - i.Anio) < 4)
  BEGIN
    ROLLBACK TRANSACTION;
    THROW 50002, 'Entre dos mundiales tiene que haber al menos 4 años.', 1;
  END
END;

Trigger INSTEAD OF DELETE (multifila)

Final 30/07/2024 (respuesta de la cátedra): poder borrar una provincia con un DELETE, aunque tenga ciudades.

-- Motor: SQL Server (T-SQL)
CREATE TRIGGER tr_provincia_borrar ON Provincia
INSTEAD OF DELETE
AS
BEGIN
  SET NOCOUNT ON;
  -- primero los hijos de TODAS las provincias que se quieren borrar
  DELETE FROM Ciudad
   WHERE idpcia IN (SELECT idpcia FROM deleted);
  -- después las provincias (esto no vuelve a disparar el trigger)
  DELETE FROM Provincia
   WHERE idpcia IN (SELECT idpcia FROM deleted);
END;

    🟪 Respuestas modelo

    Desarrolle dos objetos de BD que aseguren la integridad de los datos 3 veces

    1. Constraints. Son reglas declarativas que el motor verifica en cada INSERT y UPDATE, sin programar nada. PRIMARY KEY asegura la integridad de entidad (cada fila única y sin NULL); FOREIGN KEY, la referencial (el valor referenciado tiene que existir, y no deja borrar un padre con hijos); UNIQUE evita repetidos en claves alternas; CHECK valida una condición sobre la fila (por ejemplo, cantidad >= 0); NOT NULL y DEFAULT completan la integridad de dominio. Son la primera opción: simples y eficientes. Su límite es que solo miran la fila o una referencia puntual.

    2. Triggers. Son bloques de código asociados a una tabla que se disparan con INSERT, UPDATE o DELETE, dentro de la misma transacción. Con las tablas inserted y deleted pueden validar reglas que involucran varias filas o tablas (por ejemplo, que una materia no esté en dos laboratorios el mismo día) y hacer ROLLBACK si se violan. Los AFTER validan después de la operación; los INSTEAD OF la reemplazan (por ejemplo, para borrar primero los hijos). Hay que escribirlos para varias filas.

    (La cátedra también aceptó stored procedures, si toda modificación pasa por ellos, y vistas WITH CHECK OPTION.)

    Concepto de constraint y tres ejemplos 29/07/2025

    Una constraint es una restricción declarada sobre una tabla o columna que el motor hace cumplir automáticamente: rechaza cualquier INSERT, UPDATE o DELETE que la viole. Implementa las reglas de integridad sin programar.

    • PRIMARY KEY: la columna (o columnas) que identifica cada fila; no admite repetidos ni NULL. Ej.: CONSTRAINT pk_pais PRIMARY KEY (idpais).
    • FOREIGN KEY: el valor tiene que existir como clave en otra tabla. Ej.: FOREIGN KEY (idpais) REFERENCES Pais(idpais) impide cargar una provincia de un país inexistente o borrar un país con provincias.
    • CHECK: condición que debe cumplir cada fila. Ej.: CHECK (habitantes > 0).

    Otras: UNIQUE (sin repetidos, admite un NULL en SQL Server), DEFAULT y NOT NULL.

    Salió el 29/07/2025.

    Triggers: concepto, funcionalidad y usos 26/02/2019

    Un trigger es un procedimiento asociado a una tabla (o vista) que se ejecuta automáticamente ante un evento: INSERT, UPDATE o DELETE. Corre dentro de la misma transacción que la sentencia que lo disparó, así que si hace ROLLBACK se deshace todo.

    En SQL Server se dispara una vez por sentencia y accede a las filas afectadas mediante las tablas virtuales inserted (filas nuevas) y deleted (filas viejas). Puede ser AFTER, que corre después de la operación y de las constraints (puede haber varios por evento), o INSTEAD OF, que la reemplaza (uno por evento; también sobre vistas).

    Usos: reglas de integridad que una constraint no puede expresar (varias filas o tablas), emular una FK sin cambiar la estructura, auditoría (registrar quién cambió qué), mantener datos derivados (totales) e impedir operaciones (por ejemplo, borrar de una tabla de auditoría).

    Salió el 26/02/2019.

    Diferencias entre un stored procedure y una función 25/09/2019

    Los dos son código T-SQL guardado en la base, compilado y con parámetros. Diferencias:

    • La función siempre devuelve un valor (escalar) o una tabla, y se usa dentro de una expresión: en el SELECT, WHERE o FROM. El SP se ejecuta con EXEC; puede devolver conjuntos de resultados, parámetros OUTPUT y un código de retorno.
    • La función no puede modificar tablas (INSERT, UPDATE, DELETE), ni manejar transacciones, ni usar TRY/CATCH: no puede tener efectos laterales. El SP puede hacer todo eso.
    • Una función puede llamarse desde un SP; un SP no puede llamarse desde una función.

    Por eso para cálculos reutilizables se usa una función, y para procesos que cambian datos, un SP (el práctico del 04/12/2019 era justamente una función que hacía UPDATE: incorrecto).

    Salió el 25/09/2019.

    Explique el objeto vista y su relación con la seguridad e integridad 21/02/2018

    Una vista es una consulta SELECT guardada con nombre, que se usa como si fuera una tabla. No almacena datos: cada vez que se la consulta, el motor ejecuta su consulta, así que siempre muestra datos actuales.

    Usos: simplificar consultas complejas (joins, agregados) para los usuarios; dar independencia lógica, porque si cambia la estructura se ajusta la vista y no los programas; y seguridad: se da permiso sobre la vista y no sobre las tablas, así el usuario ve solo las filas y columnas permitidas (por ejemplo, empleados sin el sueldo).

    Integridad: con WITH CHECK OPTION, la vista rechaza los INSERT y UPDATE hechos a través de ella que no cumplan su WHERE. Se puede insertar en una vista si es simple (una tabla, sin agregados ni DISTINCT) o mediante un trigger INSTEAD OF.

    Salió el 21/02/2018. «Dos objetos para seguridad» (vistas y SP) salió el 25/09/2019.

    Compare una vista y un snapshot 2 veces

    La vista guarda solo la definición de una consulta: no ocupa espacio con datos y, como se ejecuta cada vez que se la usa, siempre muestra la información al día. El costo es que una consulta pesada se recalcula en cada uso.

    El snapshot (vista materializada) guarda físicamente el resultado de la consulta en un momento dado: es una foto de los datos. Ocupa espacio y puede quedar desactualizado, por lo que se refresca periódicamente o a pedido, pero leerlo es rápido porque no recalcula nada.

    La vista sirve para seguridad, simplificación e independencia lógica sobre datos operativos. El snapshot sirve para reportes y consultas pesadas, réplicas en otros servidores y conservar el estado de los datos a una fecha (por ejemplo, al cierre del mes). En SQL Server, lo más parecido son las vistas indexadas y los database snapshots.

    Salió el 22/12/2022 y el 27/02/2024.

    3. Escribí el código: final 03/12/2024, «una materia no puede estar en el mismo día en laboratorios diferentes», sin alterar la estructura

    Tabla Horario(labo_id, dia_id, turno, materia_id). Escribilo en papel antes de mirar.

    Ver una solución 
    -- Motor: SQL Server (T-SQL)
CREATE TRIGGER tr_horario_un_labo_por_dia ON Horario
AFTER INSERT, UPDATE
AS
BEGIN
  SET NOCOUNT ON;
  IF EXISTS (SELECT 1
               FROM inserted i
               JOIN Horario h
                 ON h.materia_id = i.materia_id
                AND h.dia_id     = i.dia_id
                AND h.labo_id   <> i.labo_id)
  BEGIN
    ROLLBACK TRANSACTION;
    THROW 50003, 'La materia ya está asignada ese día en otro laboratorio.', 1;
  END
END;

    Se compara contra toda la tabla (que en un AFTER ya incluye las filas nuevas): así detecta tanto un choque con filas viejas como dos filas nuevas que chocan entre sí. «Sin alterar la estructura» = nada de agregar constraints: trigger.

    4. Escribí el código: final 12/12/2023, claves consecutivas desde 1 en Numeros(clave PK, valor)

    Ya existe un INSTEAD OF INSERT que no se puede modificar y una constraint que impide claves no positivas.

    Ver una solución 
    -- Motor: SQL Server (T-SQL)
CREATE TRIGGER tr_numeros_consecutivos ON Numeros
AFTER INSERT
AS
BEGIN
  SET NOCOUNT ON;
  -- claves positivas y sin repetir (PK): 1..n sin huecos  <=>  MAX = COUNT
  IF (SELECT MAX(clave) FROM Numeros) <> (SELECT COUNT(*) FROM Numeros)
  BEGIN
    ROLLBACK TRANSACTION;
    THROW 50004, 'Las claves tienen que ser consecutivas desde 1.', 1;
  END
END;

    ¿Por qué AFTER? Porque ya hay un INSTEAD OF INSERT y no puede haber dos. ¿Por qué alcanza MAX = COUNT? Si hay n claves positivas distintas y la mayor es n, tienen que ser exactamente 1, 2, …, n.
