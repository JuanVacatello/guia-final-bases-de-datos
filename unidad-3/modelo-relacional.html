Unidad 3: Diseño de datos

Modelo relacional e integridad

Tablas, claves y reglas de integridad. Poca teoría directa, pero es el vocabulario de toda la unidad 4: si sabés qué integridad cubre cada constraint, la pregunta de objetos de BD sale sola.

🟦 En 30 segundos Diagramas Tablas 🟥 Trampas 🟪 Respuestas modelo 🟩 Ejercitá

🟦 En 30 segundos

  • El modelo relacional (Codd, 1970) guarda todo en relaciones (tablas): filas (tuplas) con atributos (columnas), cada uno con un dominio (valores posibles). Se consulta con álgebra relacional, que el motor traduce del SQL.
  • Claves: candidata (identifica cada fila, mínima), primaria (la candidata elegida), alternas (las candidatas no elegidas) y foránea (referencia la clave de otra tabla).
  • Reglas de integridad: de entidad (la PK no se repite ni es NULL), referencial (cada FK apunta a algo que existe, o es NULL), de dominio (tipo, NOT NULL, CHECK) y semántica o de negocio (reglas propias: triggers).
  • Las restricciones pueden ser por columna, por tabla o entre tablas («solo por tabla» es F, oficial dos veces).

    Explique el concepto de dominio y las reglas de integridad de entidad, referencial y semántica 21/02/2018

    El dominio es el conjunto de valores válidos de un atributo: su tipo de dato, su rango y si admite NULL. La integridad de dominio exige que cada valor pertenezca a él; se implementa con el tipo, NOT NULL, CHECK y DEFAULT.

    Integridad de entidad: cada fila debe poder identificarse, así que la clave primaria no puede repetirse ni ser NULL. Se implementa con PRIMARY KEY.

    Integridad referencial: el valor de una clave foránea debe ser NULL o existir como clave en la tabla referenciada; así no quedan filas «huérfanas». Se implementa con FOREIGN KEY, que rechaza el INSERT o UPDATE de un hijo sin padre y el DELETE de un padre con hijos (o lo propaga con ON DELETE CASCADE). Si no se puede usar la FK, se emula con triggers.

    Integridad semántica: reglas propias del negocio (por ejemplo, «el campeón y el subcampeón no pueden ser el mismo» o «una materia no puede estar en dos laboratorios el mismo día»). Si involucra una sola fila, CHECK; si involucra varias filas o tablas, triggers.

    Desarrolle el concepto de modelo relacional 2022

    El modelo relacional, propuesto por Codd, representa los datos como un conjunto de relaciones (tablas). Cada relación tiene atributos (columnas) definidos sobre un dominio y un conjunto de tuplas (filas) sin repetir y sin orden. Las relaciones entre entidades no son punteros: se expresan con valores, a través de claves foráneas que referencian claves primarias.

    Tiene tres partes: la estructura (relaciones, atributos, dominios, claves), la integridad (reglas de entidad, referencial, de dominio y semánticas, que el motor hace cumplir con constraints) y la manipulación, mediante el álgebra relacional (selección, proyección, producto, join, unión, diferencia), sobre la que se construye SQL.

    Su principal ventaja es la independencia de los datos: el usuario dice qué datos quiere y no cómo encontrarlos; el motor decide el camino (plan de ejecución). Para diseñar se aplica normalización, que evita redundancia y anomalías de actualización.
