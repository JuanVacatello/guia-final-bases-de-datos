Simulacro 1

1a. V/F (justificar)

«El nivel de aislamiento REPEATABLE READ acepta lecturas fantasmas.»

Era V (respuesta de la cátedra, 30/07/2024). Bloquea las filas que leyó, pero no impide que otra transacción inserte filas nuevas que cumplan el WHERE. Eso solo lo evita SERIALIZABLE.

1b. V/F (justificar)

«Si el árbol de Huffman posee N niveles, entonces el código de mayor tamaño posee N bits.»

Era F (27/09/2023). Tiene N − 1 bits: la raíz es el nivel 1 y no aporta ningún bit.

2a. Teoría (2 puntos)

Compare procesos OLTP y OLAP en cuanto a su utilización y diseño de base de datos.

Qué tenía que tener
  • OLTP: operación diaria, muchas transacciones cortas, datos actuales, ACID y concurrencia, modelo normalizado.
  • OLAP: análisis y decisiones, consultas enormes, datos históricos, solo lectura, modelo estrella desnormalizado, cubos.
  • Cómo se conectan: ETL hacia un Data Warehouse. Un ejemplo de cada uno.

Respuesta completa en OLAP.

2b. Teoría (2 puntos)

Realice una comparación entre hashing y árbol B como método de acceso a datos.

Qué tenía que tener
  • Hashing: h(k) → posición, O(1) por igualdad, colisiones y cómo se resuelven, tamaño fijo, claves únicas.
  • Árbol B: n-ario balanceado, nodo = página, O(log n), split y fusión, B+ con hojas encadenadas.
  • Conclusión: igualdad sobre clave única → hashing; rangos, orden, duplicados → árbol B+.

Respuesta completa en Hashing.

3a. Práctica (2 puntos)

TABLITAFINAL(numero INT UNIQUE), vacía y sin triggers. Indique si hay errores y el contenido final.

INSERT INTO tablitafinal VALUES (1);
INSERT INTO tablitafinal VALUES (3);
INSERT INTO tablitafinal VALUES (NULL);
UPDATE tablitafinal SET numero = ISNULL(numero, 5) + 1
 WHERE 1 = 1 OR numero IS NOT NULL AND numero > 0;
INSERT INTO tablitafinal VALUES (NULL);
COMMIT;
Ver la solución

Queda NULL, 2, 4, 6; solo falla el COMMIT (no hay transacción abierta). AND va antes que OR: el WHERE es siempre verdadero y el NULL pasa a 6, así que el último NULL entra. (22/02/2023 y 18/02/2025.)

3b. Práctica (2 puntos)

Pais(idpais, detalle), Provincia(idpcia, idpais, detalle, habitantes), Ciudad(idciudad, idpcia, detalle), con sus FK. Cree los objetos necesarios para poder borrar una provincia con un comando DELETE.

Ver la solución 
-- Motor: SQL Server (T-SQL)
CREATE TRIGGER tr_provincia_borrar ON Provincia
INSTEAD OF DELETE
AS
BEGIN
  SET NOCOUNT ON;
  DELETE FROM Ciudad    WHERE idpcia IN (SELECT idpcia FROM deleted);
  DELETE FROM Provincia WHERE idpcia IN (SELECT idpcia FROM deleted);
END;

Respuesta de la cátedra (30/07/2024). Restá puntos si: usaste un SP (no funciona con DELETE), un AFTER (la FK falla antes) o una variable en vez de IN (no es multifila).

«Para una misma tabla y evento, solo puede haber un trigger AFTER.»

Era F (oficial, 22/12/2022: el alumno puso V y le restaron). Puede haber varios AFTER por evento; el que es único es INSTEAD OF.

1b. V/F (justificar)

«Conviene, en términos de velocidad, buscar en una estructura de hash por una clave que buscar en una estructura de árbol B+.»

Era F (respuesta de la cátedra, 30/07/2024). «Una clave» no dice que sea única ni que exista: con claves repetidas o muchas colisiones, hashing no conviene. Con «clave única existente» (04/12/2019) era V.

2a. Teoría (2 puntos)

Indique los distintos niveles de aislamiento de un DBMS indicando claramente qué tipos de bloqueos se ejecutan en cada uno.

Qué tenía que tener
  • Los 4 niveles y las 3 anomalías que evita cada uno (sucia, no repetible, fantasma).
  • Escribir siempre toma bloqueo exclusivo hasta el final, en cualquier nivel.
  • Lectura: RU no pide compartido; RC lo suelta al terminar de leer; RR lo mantiene hasta el COMMIT; SERIALIZABLE además bloquea el rango.

3a. Práctica (2 puntos)

Persona(id, fecha_nacimiento, apellido, nombre, su_padre_es), donde su_padre_es es FK a Persona. Realice una consulta que muestre las personas con su abuelo paterno (nombre y apellido de ambos).

Ver la solución 
SELECT h.nombre, h.apellido,
       a.nombre AS abuelo_nombre, a.apellido AS abuelo_apellido
  FROM Persona h
  JOIN Persona p ON h.su_padre_es = p.id
  JOIN Persona a ON p.su_padre_es = a.id;

3b. Práctica (2 puntos)

El SP descuenta_stock hace: BEGIN TRAN; IF EXISTS (SELECT … cantidad >= @cant) → UPDATE que descuenta y COMMIT; si no, ROLLBACK. El nivel de aislamiento se define en cada ejecución. ¿Cuál es correcta? 1) siempre funciona bien; 2) puede dejar stock negativo; 3) con algún nivel puede dar interbloqueo; 4) todas. Justifique.

Ver la solución

2 y 3. READ COMMITTED: dos ejecuciones validan el mismo stock y las dos descuentan. REPEATABLE READ o SERIALIZABLE: las dos retienen el compartido y piden exclusivo → deadlock. Arreglo: validar y descontar en un solo UPDATE y mirar @@ROWCOUNT. (28/02/2023 y 01/08/2023.)

3a. Práctica (2 puntos)

Para ver la ocupación del laboratorio 401 por día y turno se escribió esta consulta. a) no compila; b) da error en ejecución; c) se ejecuta pero no retorna lo pedido; d) retorna lo solicitado. Justifique.

SELECT d.dia_nombre,
       ISNULL(m1.detalle, 'LIBRE'), ISNULL(m2.detalle, 'LIBRE')
  FROM Dia d
  LEFT JOIN Horario h1 ON h1.dia_id = d.dia_id AND h1.labo_id = 401 AND h1.turno = 0
  JOIN Materia m1      ON m1.materia_id = h1.materia_id
  LEFT JOIN Horario h2 ON h2.dia_id = d.dia_id AND h2.labo_id = 401 AND h2.turno = 1
  JOIN Materia m2      ON m2.materia_id = h2.materia_id
Ver la solución

c). Los JOIN con Materia comparan contra un NULL cuando el turno está libre: esas filas desaparecen y «LIBRE» nunca se muestra. Se arregla con LEFT JOIN en los dos joins con Materia. (03/12/2024; la misma trampa el 29/07/2025.)

3b. Práctica (2 puntos)

MundialFutbol(IdMundial, Anio, PaisCampeon, PaisSubCampeon). Implante la regla: el campeón y el subcampeón no pueden ser el mismo y la diferencia entre dos mundiales no puede ser menor a 4 años. La regla se cumple hoy y acceden n aplicaciones.

Ver la solución 
-- Motor: SQL Server (T-SQL)
CREATE TRIGGER tr_mundial_reglas ON MundialFutbol
AFTER INSERT, UPDATE
AS
BEGIN
  SET NOCOUNT ON;
  IF EXISTS (SELECT 1 FROM inserted WHERE PaisCampeon = PaisSubCampeon)
     OR EXISTS (SELECT 1
                  FROM inserted i
                  JOIN MundialFutbol m
                    ON m.IdMundial <> i.IdMundial
                   AND ABS(m.Anio - i.Anio) < 4)
  BEGIN
    ROLLBACK TRANSACTION;
    THROW 50001, 'Regla de mundiales violada.', 1;
  END
END;

La primera regla también puede ser un CHECK (PaisCampeon <> PaisSubCampeon). «n aplicaciones» quiere decir que tiene que estar en la base, no en un programa. (22/12/2022.)
