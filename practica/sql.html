Plantillas de T-SQL

Escribilas a mano un par de veces: en el examen no hay computadora. Todas son para SQL Server; aclarálo en la hoja («Motor: SQL Server»).

1. Trigger AFTER que valida y deshace (multifila)

Para reglas que miran otras filas u otras tablas. Siempre EXISTS contra inserted, nunca una variable.

-- Motor: SQL Server (T-SQL)
CREATE TRIGGER tr_tabla_regla ON Tabla
AFTER INSERT, UPDATE
AS
BEGIN
  SET NOCOUNT ON;
  IF EXISTS (SELECT 1
               FROM inserted i
               JOIN Tabla t ON /* la condición que rompe la regla */ t.id <> i.id)
  BEGIN
    ROLLBACK TRANSACTION;
    THROW 50001, 'Explicación de la regla violada.', 1;
  END
END;
2. Emular una FK con triggers (sin tocar la estructura)

Finales 26/02/2019 y 26/02/2020. Hacen falta dos triggers: en el hijo (que exista el padre) y en el padre (que no queden huérfanos).

-- Motor: SQL Server (T-SQL)
-- en el hijo: el padre tiene que existir
CREATE TRIGGER tr_t2_existe_padre ON T2
AFTER INSERT, UPDATE
AS
BEGIN
  SET NOCOUNT ON;
  IF EXISTS (SELECT 1 FROM inserted i
              WHERE i.id_t1 IS NOT NULL
                AND NOT EXISTS (SELECT 1 FROM T1 WHERE T1.id = i.id_t1))
  BEGIN
    ROLLBACK TRANSACTION;
    THROW 50010, 'El registro referenciado de T1 no existe.', 1;
  END
END;
GO
-- en el padre: no dejar hijos huérfanos
CREATE TRIGGER tr_t1_sin_huerfanos ON T1
AFTER DELETE, UPDATE
AS
BEGIN
  SET NOCOUNT ON;
  IF EXISTS (SELECT 1 FROM T2
              WHERE T2.id_t1 IN (SELECT id FROM deleted)
                AND NOT EXISTS (SELECT 1 FROM T1 WHERE T1.id = T2.id_t1))
  BEGIN
    ROLLBACK TRANSACTION;
    THROW 50011, 'Hay registros de T2 que apuntan a ese T1.', 1;
  END
END;
3. Trigger INSTEAD OF DELETE (borrar padre con hijos)

Finales 12/03/2018 y 30/07/2024 (respuesta oficial). Con un SP no vale: tiene que funcionar con la sentencia DELETE.

-- Motor: SQL Server (T-SQL)
CREATE TRIGGER tr_provincia_borrar ON Provincia
INSTEAD OF DELETE
AS
BEGIN
  SET NOCOUNT ON;
  DELETE FROM Ciudad    WHERE idpcia IN (SELECT idpcia FROM deleted);
  DELETE FROM Provincia WHERE idpcia IN (SELECT idpcia FROM deleted);
END;
4. Stored procedure con transacción y TRY/CATCH

Finales 28/02/2023 y 01/08/2023. Validar y modificar en la misma sentencia: es lo que evita el stock negativo sin deadlocks.

-- Motor: SQL Server (T-SQL)
CREATE PROCEDURE sp_descontar_stock
  @prod_id CHAR(8), @depo_id INT, @cant INT
AS
BEGIN
  SET NOCOUNT ON;
  BEGIN TRY
    BEGIN TRANSACTION;
    UPDATE Stock
       SET cantidad = cantidad - @cant
     WHERE id_producto = @prod_id
       AND id_deposito = @depo_id
       AND cantidad >= @cant;
    IF @@ROWCOUNT = 0
      THROW 50003, 'No hay stock suficiente en ese depósito.', 1;
    COMMIT TRANSACTION;
  END TRY
  BEGIN CATCH
    IF @@TRANCOUNT > 0 ROLLBACK TRANSACTION;
    THROW;
  END CATCH
END;
5. Cursor (cuando hay que decidir fila por fila)

Final 23/07/2024: en un INSTEAD OF INSERT, cada login se procesa según el estado del usuario. Usalo solo si no sale con una sentencia.

-- Motor: SQL Server (T-SQL)
DECLARE @id INT, @cant INT;
DECLARE c CURSOR LOCAL FAST_FORWARD FOR
  SELECT id, cantidad FROM inserted;
OPEN c;
FETCH NEXT FROM c INTO @id, @cant;
WHILE @@FETCH_STATUS = 0
BEGIN
  -- lógica para una fila
  FETCH NEXT FROM c INTO @id, @cant;
END
CLOSE c;
DEALLOCATE c;
6. CTE recursiva (jerarquías de profundidad desconocida)

Finales 02/08/2021 (entrenadores: «No resuelve la recursividad», 1/5 al que no la usó) y 10/12/2024 (ciclos padre-hijo).

-- Motor: SQL Server (T-SQL)
-- todos los descendientes de la persona @id, con su nivel
WITH descendientes (id, nombre, nivel) AS (
  SELECT id, nombre, 1                         -- ancla: los hijos directos
    FROM Persona
   WHERE su_padre_es = @id
  UNION ALL
  SELECT p.id, p.nombre, d.nivel + 1           -- recursión: hijos de los anteriores
    FROM Persona p
    JOIN descendientes d ON p.su_padre_es = d.id
)
SELECT COUNT(*) AS cantidad, MAX(nivel) AS profundidad
  FROM descendientes;

Ojo: un CTE tiene que ir seguido directamente de SELECT, INSERT, UPDATE o DELETE (no de un IF). Para usarlo en un IF, guardá el resultado en una variable. Ejemplo completo en el trigger anticiclos de Finales resueltos.

7. Vista (con alias y WITH CHECK OPTION)

Final 11/02/2025: «crear una vista … con alias en cada columna». La cátedra aceptó la vista WITH CHECK OPTION como objeto de integridad.

-- Motor: SQL Server (T-SQL)
CREATE VIEW vw_stock_positivo AS
SELECT id_producto AS producto,
       id_deposito AS deposito,
       cantidad    AS cantidad
  FROM Stock
 WHERE cantidad >= 0
WITH CHECK OPTION;

🟩 Antes de entregar un práctico escrito

  1. Escribí el motor arriba: «Motor: SQL Server (T-SQL)».
  2. Multifila: ningún SELECT @x = … FROM inserted. Siempre EXISTS, IN o JOIN.
  3. Todos los eventos: ¿qué INSERT, UPDATE o DELETE, en qué tablas, pueden romper la regla?
  4. «Se cumple hoy» = no hace falta arreglar datos. «Los datos NO están correctos» = primero corregir (como en los duplicados de 2023) y después la regla.
  5. Concurrencia: si lee y después escribe, ¿qué pasa si dos lo ejecutan a la vez? Validá y modificá en la misma sentencia.
  6. GROUP BY: todo lo del SELECT que no es agregado tiene que estar agrupado (y agrupá por id, no solo por nombre).
  7. Los que no tienen: LEFT JOIN con ISNULL para mostrar 0 o un texto, o NOT EXISTS.
